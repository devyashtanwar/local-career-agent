# Contributing

Start with an issue describing a concrete workflow, reproduction and expected
behavior. Use synthetic fixtures. Preserve failures; do not turn a retry-until-pass
demo into an accuracy claim. Include hardware, context, runtime, quantization,
model revision and whether results are measured or publisher-reported.

For changes: run both unittest suites and shell syntax checks from the README.
Explain effects on network access, file permissions, account authority and restart
behavior. Fresh-host installation results should be recorded separately from
unit tests. Never enable accounts, autostart, elevated execution or cloud fallbacks
as an incidental fix. Avoid multiple competing schedulers or job ledgers.

Keep dependency licenses/provenance and exact versions. Reference upstream projects
before copying code, and check their license. Prefer small reviewable increments.
Do not contribute fabricated qualifications, hidden ATS qualification stuffing,
platform-detection evasion, CAPTCHA bypass or concealed assessment assistance.
